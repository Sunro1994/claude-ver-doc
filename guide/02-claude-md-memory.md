# `CLAUDE.md` / `MEMORY.md` 활용법

두 파일은 역할이 완전히 다르다.

- **`CLAUDE.md`** — 사람이 직접 작성. 규칙·컨벤션·가치관.
- **`MEMORY.md` + `{name}.md`** — Claude가 자동 작성. 대화에서 학습한 사실.

## CLAUDE.md에 넣는 것

- 코딩 스타일, 아키텍처 규칙
- 커밋·PR 관례
- 응답 어조·언어
- 절대 하지 말 것 (do-not-do)

## CLAUDE.md에 넣지 말 것

- 시크릿, 개인정보
- 자주 바뀌는 상태(TODO 목록, 진행 중 이슈)
- 코드에서 유추 가능한 정보

## MEMORY 4가지 타입

| 타입 | 저장 시점 | 예시 |
|---|---|---|
| **user** | 사용자 정보 | "10년차 백엔드, Kotlin, React 신규" |
| **feedback** | 사용자 피드백 | "테스트에서 DB 목킹 금지 — 지난 분기 사고" |
| **project** | 프로젝트 사실 | "3월 5일 mobile 릴리스 브랜치 컷" |
| **reference** | 외부 참조 | "파이프라인 버그는 Linear INGEST" |

## 인덱스 관리

- `MEMORY.md` = 인덱스 (한 줄씩 링크만)
- 실제 내용은 `{name}.md`에 저장
- 200줄 이후는 잘리므로 인덱스는 간결히

## 왜 두 개로 나누는가

CLAUDE.md는 결정된 규칙, MEMORY는 진행 중 학습.
CLAUDE.md에 학습을 쌓으면 문서가 무거워지고 신호가 흐려진다.
